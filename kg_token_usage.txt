READ THIS BEFORE USING THE MEASURED COLUMN
------------------------------------------------------------------------------
dspy caches completions keyed on prompt text, and cache hits are invisible to
the usage tracker (kg_graph.py:872, :935). The identical substrate that makes
this ablation clean also makes the prompts identical, so arms 2 and 3 replayed
completions cached by collection 28's earlier run.

Their MEASURED totals are therefore marginal cost against a warm cache, NOT
what those arms cost to build from scratch. Collection 28 ran when these
prompts were novel, so its figure is a true cold-cache cost - corroborated by
the re-OCR arm of the earlier OCR benchmark (different text, also cold), which
landed at 391,175. That collection has since been deleted; the figure is from
its run log, recorded in commit 7e5dbdb.

Prompt chars are a pure function of packing and are unaffected by caching, so
they are the honest basis for comparing arms. ESTIMATED scales collection 28's
cold cost by the prompt-char ratio.

WHAT THE ARMS ACTUALLY SHOW
------------------------------------------------------------------------------
* Whole corpus buys 22% more relations (719 -> 880) and 28% more entities for
  ~44% more tokens. Diminishing, but not badly so.
* Random 40% is CHEAPER than heuristic 40% (498k vs 571k prompt chars) despite
  the same 8/12 split, because the heuristic preferentially picks large,
  representative documents while the draw took smaller ones. It returns 6%
  fewer relations for 13% fewer tokens - close to proportional, which is weak
  evidence that the ranking is not buying much per token on this corpus.
* That random draw shares 5 of 8 documents with the heuristic pick (chance
  expectation 3.2/8), so the contrast rests on only 3 swapped documents. One
  draw is a sample of size 1; do not over-read it.


CAVEATS
------------------------------------------------------------------------------
* chunksProcessed is not comparable across arms: kg_graph counts chunks for
  full-text documents but ENTRIES for summarized ones (_call_batches:729).
  Omitted from this table for that reason.
* The whole-corpus arm packs 994 of 1008 chunks - bibliography and empty-body
  chunks are dropped from every path (_call_batches:699-702).
* Arm 1 spends zero tokens by construction. Retrieval still works there:
  buildGraphIndex returns null on an absent graph and graphFacts short-circuits,
  so the chat falls back to vector + BM25.
* Entity resolution and predicate normalization run locally (NLI
  cross-encoder), cost no API tokens, and do change the final counts here.
* To replace ESTIMATED with measured cold numbers, clear ~/.dspy_cache and
  rebuild arms 2 and 3. That regenerates their graphs, so the entity and
  relation counts above would be resampled too.
